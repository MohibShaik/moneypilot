# MoneyPilot Backend — Deployment (Render + Neon)

Deploy the Spring Boot API as a free, public HTTPS service:

- **App host:** Render (free Docker web service)
- **Database:** Neon (free, persistent PostgreSQL — no 30-day expiry)

The app is fully env-driven, binds to `${PORT}`, and runs Flyway migrations
(`V1`, `V2`) automatically on startup, so a fresh Neon database is schema-ready
on first boot.

---

## 1. Create the database on Neon

1. Sign up at [neon.com](https://neon.com) (no credit card).
2. Create a project (choose a region close to your Render region).
3. Open **Connection Details** and copy the connection string. It looks like:

   ```
   postgresql://<user>:<password>@<host>.neon.tech/<db>?sslmode=require
   ```

4. From it, derive the three values Render will need:
   - **MONEYPILOT_DB_URL** (JDBC form, keep SSL):
     `jdbc:postgresql://<host>.neon.tech/<db>?sslmode=require`
   - **MONEYPILOT_DB_USERNAME** = `<user>`
   - **MONEYPILOT_DB_PASSWORD** = `<password>`

   > Note the JDBC URL starts with `jdbc:postgresql://` and does **not** include
   > the user/password (those go in the username/password vars).

---

## 2. Deploy the app on Render

### Option A — Blueprint (recommended)

1. Push this repo to GitHub/GitLab.
2. In Render, **New → Blueprint**, point it at the repo. Render reads
   `render.yaml` and provisions the `moneypilot-backend` web service.
3. When prompted, fill in the three `sync:false` env vars from step 1
   (`MONEYPILOT_DB_URL`, `MONEYPILOT_DB_USERNAME`, `MONEYPILOT_DB_PASSWORD`).
   `MONEYPILOT_JWT_SECRET` is auto-generated.
4. Deploy. The first build compiles the jar in Docker (a few minutes).

### Option B — Manual web service

1. **New → Web Service**, connect the repo.
2. Settings:
   - **Root Directory:** `backend`
   - **Runtime:** Docker (Render auto-detects `backend/Dockerfile`)
   - **Health Check Path:** `/api/v1/health`
   - **Instance Type:** Free
3. Add env vars (step 1 values) plus a strong `MONEYPILOT_JWT_SECRET`
   (≥ 32 chars for HS256).
4. Create the service.

## 3. Required environment variables

| Variable | Required | Example / notes |
| --- | --- | --- |
| `MONEYPILOT_DB_URL` | yes | `jdbc:postgresql://ep-xxx.neon.tech/moneypilot?sslmode=require` |
| `MONEYPILOT_DB_USERNAME` | yes | Neon user |
| `MONEYPILOT_DB_PASSWORD` | yes | Neon password |
| `MONEYPILOT_JWT_SECRET` | yes | ≥ 32 chars; generated by Render in the blueprint |
| `MONEYPILOT_JWT_TTL` | no | default `PT15M` |
| `MONEYPILOT_CORS_ALLOWED_ORIGINS` | no | default `*` (open); set specific origins to lock down |
| `PORT` | auto | injected by Render; the app binds to it |

## 4. Verify the deployment

Once live, Render gives a URL like `https://moneypilot-backend.onrender.com`.

- **Health:** `GET https://<app>.onrender.com/api/v1/health` → `200`
- **Swagger UI:** open `https://<app>.onrender.com/swagger-ui.html`
- **OpenAPI spec:** `https://<app>.onrender.com/v3/api-docs`

Smoke test with the real API:

```bash
BASE=https://<app>.onrender.com

# Register
curl -s -X POST $BASE/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"password1","displayName":"Demo"}'

# Login -> copy data.accessToken
curl -s -X POST $BASE/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@example.com","password":"password1"}'

# Authenticated call
curl -s $BASE/api/v1/dashboard -H "Authorization: Bearer <accessToken>"
```

## 5. Free-tier notes & gotchas

- **Cold starts:** the free web service sleeps after ~15 min idle. The first
  request afterward takes ~30–60s while it wakes. Fine for dev/demo. To avoid
  it, upgrade the instance or ping the health endpoint periodically.
- **Neon storage:** 0.5 GB per project on the free plan, persistent (no expiry).
- **Neon compute** auto-suspends when idle and resumes on the next query — the
  first query after idle has a small warm-up latency (independent of Render's
  cold start).
- **Secrets:** never commit `MONEYPILOT_JWT_SECRET` or DB credentials. They live
  only in Render env vars.
- **Migrations:** Flyway runs on every boot and is idempotent. The first deploy
  against an empty Neon DB creates the full schema (V1 + V2).
- **Mobile app:** point the Expo client's API base URL at the Render URL — this
  removes the `localhost` / `10.0.2.2` / LAN-IP problem entirely, since the API
  is reachable from any device.
